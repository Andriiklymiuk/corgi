# corgi events

## corgi events

Service lifecycle as a stream, instead of polling status

### Synopsis

Reports what the stack is doing: a service starting, going ready, crashing or
being stopped. Without --follow it prints the current state once and exits.

With --follow it stays open and emits a line per transition, so a script or an
agent reacts to a crash instead of polling corgi status on a timer.

```
corgi events [flags]
```

### Examples

```
corgi events --json

corgi events --follow --json --timeout 10m
```

### Options

```

  -h, --help                help for events
      --interval duration   How often to re-read the run state while following (default 1s)
      --timeout duration    Stop following after this long (0 = until Ctrl-C)
```
