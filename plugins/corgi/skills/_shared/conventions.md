# Shared conventions

Every corgi skill follows these. A skill says "Read `../_shared/conventions.md` first"
instead of repeating them.

## No AI attribution

Everything posted or committed (ticket comments, PR/MR bodies, commit messages, review
notes, store listings) reads as if a human wrote it. Never add "generated by AI / Claude /
corgi", a Co-authored-by or AI trailer, a bot signature, a "generated by" footer, or a
robot-emoji badge. The only machine marker allowed is an invisible HTML comment used for
idempotent updates (for example `<!-- corgi-review -->`); it does not render, so it is not
attribution. Match the repo's own commit style; let pre-commit hooks format and re-stage if
they rewrite.

## manualRun is reference-only

A service or db_service with `manualRun: true` is described in `corgi-compose.yml` so the
stack is complete, but corgi never starts it and no skill changes it. Exclude it from
service maps, dependency graphs, test runs, and branches. When a fix would have to land
there, stop and flag it out of band.

## Compose preflight

Skills that read the workspace start with `ls corgi-compose.yml *.corgi-compose.yml` in
cwd. None → tell the user to open the stack folder (or run `/corgi-new`); never guess a
layout. Read only the keys you need: `services.<name>.{path,cloneFrom,manualRun,
depends_on_services}`, `db_services`, `exports` (schema in
`../corgi/references/yml-schema.md`). `corgi context --json` gives the same picture plus
each repo's branch, dirty files and service status in one call. Don't render the whole
project with `/corgi-describe` or `--describe`.

Per repo: forge from `git -C <dir> remote get-url origin` (`github.com` → `gh`, `gitlab`
→ `glab`; a batch may span both); base from
`git -C <dir> symbolic-ref --short refs/remotes/origin/HEAD`.

## Worktree gate

Before branching in a repo, check `git -C <dir> status --porcelain --untracked-files=no`.
Empty → branch in place. Dirty, or several stories touching the same repo → a worktree per
story (`corgi run|test --service-branch <svc>=<branch>`, or `git worktree add`), so the
user's uncommitted work is never disturbed. A worktree branches from clean `origin/<base>`,
so it excludes those edits: when they overlap the story's files, stop and ask the user to
commit, stash, or confirm. Never checkout off a dirty tree, delete branches, or force-push
without an explicit OK; never edit the user's own checkout while a worktree for that
branch exists.
